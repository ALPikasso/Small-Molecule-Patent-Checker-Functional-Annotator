# Small Molecule Patent Checker

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Google Colab](https://img.shields.io/badge/Google%20Colab-%23F9AB00.svg?logo=googlecolab&logoColor=white)](https://colab.research.google.com/)
[![PubChem](https://img.shields.io/badge/Data-PubChem%20PUG%20REST-blue.svg)](https://pubchem.ncbi.nlm.nih.gov/docs/pug-rest)

A lightweight Google Colab notebook that checks whether a list of small molecules is linked to patent records in PubChem. It converts each SMILES string to an InChIKey, retrieves the associated patent identifiers, fetches example patent titles, and flags likely biological activity from keywords in those titles.

The tool was used in our HDAC1 study to check whether the identified candidate compounds already appear in the patent literature (see [Publication](#publication)).

## Overview

For every compound in an input CSV file, the notebook:

1. **Converts SMILES to InChIKey** using RDKit. Invalid SMILES receive no InChIKey.
2. **Retrieves patent IDs** linked to the InChIKey through the PubChem PUG REST API (`xrefs/PatentID`).
3. **Retrieves patent titles** for up to three patents per compound through PubChem PUG View. Titles are cached, since the same patent often appears for many compounds.
4. **Tags likely activity** by searching the titles for keywords such as *inhibitor, agonist, antagonist, modulator, activator, blocker, inducer, degrader,* and *binder*.
5. **Saves the results** to `patent_check_results.csv`.

## Repository Structure

```text
├── Small_Molecule_Patent_Checker.ipynb   # Patent checking pipeline (Google Colab)
├── smiles.csv                            # Input file with a 'SMILES' column (user-provided)
└── patent_check_results.csv              # Output file (generated by the notebook)
```

## Requirements

* Python 3
* [RDKit](https://www.rdkit.org/), `pandas`, `tqdm`, `requests`
* Internet access (the notebook queries PubChem)

The first cell installs the dependencies:

```bash
pip install rdkit pandas tqdm -q
```

`requests` is preinstalled in Google Colab.

## Usage

1. Open `Small_Molecule_Patent_Checker.ipynb` in Google Colab.
2. Upload your input file as `smiles.csv`. It must contain a column named `SMILES`.

   ```csv
   SMILES
   CC(=O)Nc1ccc(O)cc1
   O=C(O)c1ccccc1OC(C)=O
   ```

3. Run all cells.
4. Download `patent_check_results.csv` when the run finishes.

## Output Columns

All columns from your input file are preserved, and the following are added:

| Column | Description |
|---|---|
| `inchikey` | InChIKey generated from the SMILES with RDKit |
| `is_patented` | `True` if at least one PubChem patent record is linked to the compound |
| `n_patents` | Total number of linked patent IDs |
| `example_patent_ids` | Up to three patent IDs, separated by `;` |
| `example_patent_titles` | Titles of those patents, separated by `\|` |
| `guessed_activity` | Activity keywords found in the example titles |

## Configurable Parameters

| Parameter | Default | Purpose |
|---|---|---|
| `MAX_PATENTS_PER_COMPOUND` | `3` | Maximum number of patents for which titles are retrieved per compound |
| `ACTIVITY_KEYWORDS` | see above | Keywords used for activity tagging |
| `retries` | `3` | Number of retry attempts for each API request |
| `time.sleep(0.2)` | 0.2 s | Delay between requests, to stay within PubChem usage limits |

## Limitations

* **Not a freedom-to-operate analysis.** The tool does not assess patent claims, legal status, jurisdiction, or expiry. A compound flagged as patented may or may not be covered by an active claim, and a compound not flagged may still fall under a broader Markush claim.
* **Exact-structure matching only.** Lookup is by full InChIKey, so stereoisomers, salts, and close analogs are treated as different compounds.
* **Depends on PubChem coverage.** Patent-to-compound links in PubChem are not exhaustive, so `is_patented = False` means "no PubChem patent link found", not "unpatented".
* **Invalid SMILES.** SMILES that RDKit cannot parse get no InChIKey and are reported as `is_patented = False`. Check for missing `inchikey` values before interpreting the results.
* **Failed requests.** Requests that still fail after the retries return no data, which can look the same as "no patents found".
* **Crude activity tagging.** `guessed_activity` is based only on keywords in up to three patent titles. Treat it as a hint for manual review, not as evidence of activity.
* **Missing titles.** Some patent records may not return a title through PUG View.
